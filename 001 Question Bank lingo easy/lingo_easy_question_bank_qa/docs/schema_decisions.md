# Schema decisions (field by field)

Source of truth for v1: `schemas/part.schema.json`, `config/blueprint.json`, `config/taxonomy.json`, `scripts/validate_part.py`.
**Principle:** the runtime bank format (v1) is unchanged, so nothing that reads it breaks. New information lives in (a) generated sidecars keyed by UUID, (b) a flat v2
export view, (c) learner/profile schemas. **No field was removed.** Decisions below are recommendations unless marked "done".

Legend - Class: S = stored authoritative, D = derived (recomputed), G = generated sidecar, R = runtime/learner only.

## B. Item-level fields (v1)

| Field | Class | Decision | Notes |
|---|---|---|---|
| `id`, `number`, `uuid` | S | keep | Item uuid5 derives from part uuid + id. |
| `prompt`, `options[]{id,text}`, `answer` | S | keep | Options are shuffled per exam for plain MC; the assembler now records `option_origin` so diagnostics still map. |
| `level.cefr` | S | keep (authoritative until a human accepts a change) | QA recommendations live in `reports/cefr_reassessment.csv`, never written here. |
| `level.band` | S | keep, **document mapping** | 1.0-9.0 in 0.5 steps; ranges A1 1.0-2.5, A2 3.0-3.5, B1 4.0-5.0, B2 5.5-6.5, C1 7.0-8.0, C2 8.5-9.0 (`config/blueprint.json`). It is an author-assigned scale, not IELTS-calibrated and not IRT. Only 17 distinct values exist. |
| `skill_tag` | S | keep, mark **legacy / mixed-dimension** | Mixes sub-skills (`inference`), formats (`fact_check`, `summary_gap`), answer types (`numbers_dates_times`) and item-construction features (`distractor_resolution`). Use `primary_subskill` from the sidecar for analytics. |
| `language_focus` | S | keep | Populated for only 22 of 1,610 items (1.4 %): grammar/vocabulary analytics are effectively empty. |
| `evidence {paragraph, quote}` | S | keep | Verified against the source for every item; presence of the quote does not prove the item is valid. |
| `explanation` | S | keep | Many are generated as "The text says: ..." - adequate for review, thin for learner feedback. |

## D. Deprecation / removal / future migration (recommendations only)

1. **Deprecate** `skill_tag` as the analytics dimension in favour of `primary_subskill` (+ `answer_type`, `item_format`). Keep the field for traceability.
2. **Split** `profile` into `bank` (placement / level_X) and `difficulty_profile` so a part's membership is not encoded in a difficulty enum.
3. **Add** a per-item integer `version` and `revision_ref` (pointer into `audit/question_change_log.jsonl`) when the team is ready to change the v1 shape; until then the part `content_hash` is the version.
4. **Add** `evidence.unit_id` for listening (turn index) so evidence can be located precisely instead of by substring.
5. **Remove** nothing now. `assets` and group `context` are the only unused fields; keep until a decision about images/gap-fill UI is made.

## E. Backward compatibility and migration notes

* v1 files remain valid for `scripts/validate_part.py --bank question_bank` (test `test_v1_bank_still_valid_for_existing_validator`).
* Question ids, uuids, part ids/uuids, source text and answer keys are unchanged (test `test_unchanged_questions_identical_and_changed_only_in_distractors`).
* The 571 logged edits (488 questions) only replaced distractor texts; each is logged with original and revised options (`audit/question_change_log.jsonl`).
* `derived.content_hash` of edited parts changed (expected). Anything caching hashes must refresh.
* API/runtime changes: `Settings.enforce_blueprint` (default on); `POST /api/exam/start` may return 409 with a structured `no_valid_exam` body; `submit` additionally writes `exams/<id>.attempt.json`.
